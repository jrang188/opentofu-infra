## Next steps (user actions, in order)

1. **Tailscale admin console:** add `tag:hermes` to `tagOwners`; create an
   auth key tagged `tag:hermes` — **reusable, non-ephemeral** (hard rule:
   ephemeral keys reap offline nodes; the VM is static). Key expiration is
   90 days max, but that only blocks *new* enrolments — the running node
   stays authenticated, so no routine rotation. Rotate only if/when the VM
   is recreated later.
2. **1Password `Development` vault:** store that key as
   `tailscale-auth-key-hermes`. Do NOT reuse the k3s `tailscale-auth-key` —
   auth keys are bound to their tags at creation and that key carries
   `tag:k8s-control-plane`.
3. **tfvars:** create `terraform/hermes/terraform.tfvars` (example file
   exists) with `tailscale_magicdns_domain` filled in, and set
   `hermes_server_type = "cx23"`, `hermes_location = "hel1"` — see "Stock"
   below.
4. **Apply** (machine must have `op` signed in; tailnet login needed
   afterwards to reach the VM): `cd terraform/hermes && tofu plan
   -out=hermes.tfplan && tofu apply hermes.tfplan`. The auth key appears
   unredacted in plan/state under `user_data` — expected, same exposure the
   k3s root accepts.
5. **Verify:** `tailscale status | grep hermes`, then
   `ssh hermes.<magicdns-domain>` (Tailscale SSH is on).
6. **Install the hermes agent** manually (Docker vs systemd undecided —
   deliberately out of Terraform's scope).
7. **After agent data lives on the box:** set
   `delete_protection = true` on `hcloud_server.hermes` (TODO comment in
   hermes.tf).

## Stock situation (why nothing is applied yet)

- Hetzner's late-2025 lineup shuffle: CX Gen2 (`cx22`) is deprecated; CX
  Gen3 (`cx23`, 2 vCPU / 4 GB / 40 GB, ~€5.99/mo incl. IPv4) is the
  replacement but **out of stock everywhere as of 2026-11-15**
  (radar.iodev.org; CAX11 too). The console only offers CPX22 at ~$20/mo —
  the Regular-Performance line, rejected as too expensive.
- Decision: **wait for CX23 stock, then apply** (user: "good enough, just
  need to run tofu apply. I'll do it when it opens up"). The API — not the
  console — is the availability check; `tofu plan` fails loudly on
  unavailable types, so just retry periodically.
- Zero-cost alternative discussed but not chosen: run hermes on the
  existing k3s cluster / home node (the original plan in
  `docs/homelab-ecosystem.md`). Revisit if the stock wait drags on.
